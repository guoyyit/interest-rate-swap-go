# interest-rate-swap-go

本地利率互换（IRS）合约的登记、计息与结算服务。维护多笔合约的完整生命周期：
起息/到期、固定端与浮动端计息、逐期利率重置、支付日历、提前终止、净额结算、
批量估值与崩溃恢复。所有金额以单一记账货币计量；市场曲线与支付日历通过接口注入。

## 快速开始

```go
cal := swap.NewWeekendCalendar()          // 支付日历（可注入节假日）
store, _ := swap.NewFileStore("journal.jsonl")
svc, _ := swap.Open(store, cal)           // 打开并自动重放日志恢复状态

id, _ := svc.CreateContract(spec)         // 登记合约（非法参数被拒绝）
svc.FixRates(resetAsOf, curve)            // 确认到期的浮动利率重置
svc.ConfirmPayments(payAsOf)              // 确认到期的支付并计算净额
settlement, _ := svc.Terminate(id, asOf, curve) // 提前终止（原子结算）
mtm, _ := svc.ValueAll(asOf, curve)       // 批量盯市估值（不改状态）
```

运行测试：`go test -race ./...`

## 合约结构

一笔合约（`ContractSpec`）由两条腿（`LegSpec`）组成，方向必须相反
（一收一付）。每条腿独立描述：

- **利率类型**：固定端（`FixedRateLeg`，合同利率 `FixedRate`）或浮动端
  （`FloatRateLeg`，重置利率 + `Spread`）。
- **计息基准**（`DayCount`）：`ACT/360`、`ACT/365F`、`30/360`（US）、
  `ACT/ACT`（ISDA，按自然年切分）。
- **支付频率**（`PayFreq`）：月、季、半年、年。
- **工作日调整**（`BDC`）：`Unadjusted`、`Following`、`ModifiedFollowing`、
  `Preceding`。
- **本金计划**（`Notional`）：分段常数的阶梯计划，支持摊还/增本；
  首段必须起始于起息日，日期严格递增，金额必须为正。
- **重置滞后**（`FixingLagDays`）：浮动端重置日领先期初的工作日数（0 表示
  当期期初定息）。

创建时校验：起息日必须早于到期日、固定利率非负、滞后非负、本金计划合法、
枚举字段有效、两腿方向相反。非法合约被拒绝且不产生任何持久化记录。

## 计息规则

- 计息期边界使用**未调整**日期，从起息日按支付频率步进；到期日不在周期
  边界时生成**短尾期**（final stub）。
- 每期应计利息 = 当期本金 × 利率 × 计息基准年分数（`[start, end)` 左闭右开）。
- 金额以最小货币单位（分）的整数存储，单期应计在计算时点按
  “四舍五入（half away from zero）” 归集到分，保证结果确定、可复现。
- 浮动端每期利率 = 重置日曲线隐含的简单复利远期利率
  `(DF(s)/DF(e) − 1) / dcf`，再加 `Spread`。

## 重置与支付日历

- **重置日** = 期初经 BDC 调整后，再向前回退 `FixingLagDays` 个工作日。
- **支付日** = 期末（未调整）经 BDC 调整后的日期。
- 同一重置日的定息结果由注入曲线唯一确定，且一旦确认即写入日志，
  之后任何操作都不会重算或改写（幂等：重复调用 `FixRates` 不产生新记录）。
- `ConfirmPayments` 要求所有到期浮动期已先定息，否则整批拒绝并报出
  缺失的期次，不会留下部分确认的中间状态。

## 净额结算与台账

- 同一合约、同一支付日的两腿现金流合并为一条净额记录
  （`PaymentPayload`）：含各腿明细（`Items`）、净额（`Net`）与
  截至该日的**累计应付**（`Cumulative`），符号约定为收正付负。
- 现金流、净额与累计均可逐期追溯（`Service.Contract` 返回不可变快照）。
- 已确认的记录只增不改：重复确认是空操作；日志重放对重复记录幂等。

## 提前终止

`Terminate(id, asOf, curve)` 以终止日曲线计算剩余净现金流现值差
（即当日盯市值）作为终止结算金额。整个状态迁移是**一条**持久化记录：
写入成功才更新内存状态，因此结算要么完整生效、要么完全不发生，
崩溃后由日志重放恢复，绝不留下部分结算的中间状态。终止后合约冻结，
不再产生新的重置或支付；重复终止返回 `ErrNotActive`。

## 估值

- `Value(id, asOf, curve)`：单笔盯市。未到期支付日的现金流按曲线贴现；
  浮动端已确认的定息用合同利率，未确认的用估值日远期利率。
- `ValueAll(asOf, curve)`：一次计算全部合约，结果与逐笔 `Value` 完全一致；
  估值是纯函数，不修改任何合约状态（有测试保证）。
- 已终止合约的盯市值为 0。

## 并发与崩溃恢复

- `Service` 内部以 `sync.RWMutex` 保护，多合约的创建、定息、确认、估值、
  终止可安全并发；同一合约的并发终止只有一个成功。
- 持久化采用**只追加日志**（WAL）：合约登记、利率重置、支付确认、终止结算
  各为一条 JSON 记录。`FileStore` 每条记录写盘后 `fsync`。
- 恢复 = 打开存储并重放日志（`Open` 自动完成）。应用函数幂等：
  重复记录不会重复记账。文件末尾的撕裂行（崩溃时未 fsync 的半条记录）
  被安全忽略，中间的损坏则报错。
- 内存态更新严格发生在记录持久化之后，因此“记录已写、内存未更新”的崩溃
  窗口由重放自动愈合。

## 市场曲线接口

```go
type Curve interface {
    DiscountFactor(asOf, d Date) float64
}
```

内置两个本地实现：`FlatCurve`（单一连续复利利率）与 `ZeroCurve`
（零利率柱点线性插值、连续复利）。远期利率由贴现因子统一推导，
保证定息与估值口径一致。日历同样以 `Calendar` 接口注入，
默认实现为周末+节假日表（`WeekendCalendar`）。

## 项目结构

- `date.go` — 民用日期类型（UTC 午夜，JSON 序列化）
- `daycount.go` — 计息基准年分数
- `calendar.go` — 日历接口、工作日调整
- `curve.go` — 曲线接口、远期利率、平曲线/零曲线
- `contract.go` — 合约/腿/本金计划类型与校验
- `schedule.go` — 计息期、重置日、支付日生成
- `store.go` — 日志记录、内存/文件存储
- `service.go` — 登记、定息、确认、终止、估值、恢复
